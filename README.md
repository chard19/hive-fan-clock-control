# Cryptone Fan Control

Корпусное охлаждение по самой горячей NVIDIA и индивидуальная защита частот ядра в HiveOS. Число карт не зашито в код: при настройке сохраняется список UUID. Один выбранный канал Linux hwmon управляет корпусными вентиляторами, в том числе через PWM-хаб.

**Статус: первая публичная версия.** Исходная версия проверялась на Gigabyte GA-Z270X-UD3, IT8686, SYS_FAN3/PWM4 и четырёх RTX 5070 Ti. Обобщённая версия проверена моделированием; на других платах физические испытания не проводились. На рабочий риг эта версия автоматически не устанавливается.

## Совместимость

- HiveOS с Python **3.11 или новее**, systemd, драйвером NVIDIA, `nvidia-smi` и `nvtool --clocksinfo`.
- Одна или несколько физических NVIDIA с доступными температурой ядра, PWM GPU и фиксацией частоты. AMD, MIG и виртуальные GPU не поддерживаются.
- Драйвер Linux должен предоставлять выбранные `pwmN` и `pwmN_enable` через `/sys/class/hwmon`. Требуется запись duty 0–255 и ручной режим `1`. Режим подключения PWM/DC задаётся заранее в BIOS; программа его не меняет.
- Настроенный HiveOS GPU AutoFan с включённым регулированием и общим `MAX_FAN`. Неподдерживаемый или недоступный источник лимитов блокирует повышение частот.
- Фиксированная частота ядра в HiveOS и штатное сопоставление устройств через PCI. Непустой `/hive-config/busid.conf` пока не поддерживается: управление приостанавливается с ошибкой сопоставления.

Совместимость определяется драйвером и доступными атрибутами, а не названием платы. Некоторые USB-контроллеры также имеют hwmon-драйвер; самостоятельный протокол USB, CoolBox и его окно HiveOS здесь не реализованы. У стандартного hwmon нет гарантированной связи между номером PWM и подписью разъёма на плате: нужный канал выбирает пользователь. См. [документацию ядра Linux](https://docs.kernel.org/hwmon/sysfs-interface.html).

## Подготовка и установка

Сначала проверьте в BIOS, что оба корпусных вентилятора надёжно запускаются при выбранном минимуме. Для другого типа вентилятора 30% может быть недостаточно. Пороги и минимум частоты нужно выбирать под свою модель GPU: **2400 МГц — исходная настройка для RTX 5070 Ti, не универсальное значение для всех NVIDIA**.

```bash
git clone https://github.com/chard19/cryptone-fan-control.git
cd cryptone-fan-control
python3 --version
python3 -m unittest discover -q
python3 configure.py --list
```

Последняя команда только читает оборудование и выводит доступные каналы: `hwmon_name`, устойчивый `device_path`, `pwm_channel` и текущий `hwmon_path`. Сверьте канал с документацией платы и ранее проверенным подключением. Программа не пытается определять его снижением скорости вентиляторов.

Например, **только если нужный разъём соответствует PWM4 на hwmon2**:

```bash
python3 configure.py --hwmon /sys/class/hwmon/hwmon2 --pwm 4 --output build \
  --target 65 --min-pwm 30 --max-pwm 100 --min-core 2400
cat build/cryptone-fan-control.json
cat build/cryptone-core-control.toml
sudo python3 install.py build
fancheck
```

`configure.py` сохраняет текущий список всех NVIDIA и идентификатор выбранного PWM. Он создаёт только новую папку; существующие файлы не перезаписывает и оборудование не изменяет. Номер `hwmonN` может поменяться при следующем запуске: служба ищет тот же чип, устройство и канал.

Установщик предназначен для **новой установки**. Он проверяет оборудование и HiveOS, отказывается перезаписывать существующую установку, сохраняет конфигурацию и исходный PWM в `/var/backups/cryptone-install-*`, затем запускает две службы. Автозапуск включается после получения свежего статуса обеих служб. При старте и остановке корпусного регулятора выбранный PWM кратко/постоянно переводится на 100%. Майнер, память, смещения ядра, лимиты мощности и настройки GPU AutoFan установщик не меняет.

При неудачной установке службы останавливаются; запрашивается полное охлаждение. Файлы и резервная копия остаются для разбора, автоматического отката к прежнему PWM нет. Если запись hwmon недоступна, программа физически не сможет изменить вентилятор. Программная защита также не работает при зависании ОС или отключении питания.

## Ежедневные команды

```bash
fancheck                 # общий короткий статус и подсказка
fancheck --json          # подробности; код 1 при предупреждении
sudo fanset 65 30 100     # цель °C, минимальный PWM %, максимальный PWM %
sudo fanset              # пошаговый ввод; Enter сохраняет значение; подтверждение
fanset --show            # сохранённые/применённые значения и состояние службы
```

Пример сокращённого вывода (числа условные):

```text
Заданные параметры FAN : 30%; 65 °C; 59%
Текущие значение FAN: 59%, 66°C

GPU 0 [00000001]: 65 °C; вентилятор 90%
  HiveOS 3050; фиксация 3050; рабочая 3045 МГц
  норма
  Максимум вентиляторов GPU: 90%

Настройка:
  Пример: fanset 65 30 100; fanset — пошагово; fanset --show — настройки.
  Предел частоты каждой GPU задаётся в HiveOS.
  Пороги, шаг и задержки ядра: nano /etc/cryptone-core-control.toml
  Настройки перечитываются за 5 с.
```

PWM — заданная доля управления, а не измеренные RPM или электрическая мощность. В корпусе используется самое горячее ядро из сохранённого списка NVIDIA. Недоступные данные обозначаются `—`; старые показания не выдаются за текущие. `fancheck` ничего не записывает. Отдельной команды `corecheck` нет.

`fanset` принимает целые числа: цель 20–70 °C, PWM 30–100%, минимум строго меньше максимума. Запись атомарная, параллельные команды исключены. Служба перечитывает настройки без перезапуска и подтверждает применённую конфигурацию. Код `fanset`: 0 — применено/отмена/показ; 1 — ошибка; 2 — сохранено, применение не подтверждено; 130 — прерывание. Действующая авария при смене настроек не сбрасывается.

## Как регулируется корпус

- Старт: 100%, затем 55%, ограниченные выбранными границами.
- Опрос каждые 5 с, допуск ±1 °C вокруг цели. Внутри допуска скорость сохраняется.
- Выше допуска: прибавление 1–3 процентных пунктов каждые 10 с в зависимости от превышения. Ниже допуска: убавление 1 пункта каждые 20 с.
- При ≥75 °C, ошибке температур, изменении состава карт или неверной конфигурации — **100% независимо от обычного максимума**.
- Возврат из аварии: три корректных измерения подряд при ≤70 °C; при цели выше 68 °C порог равен цели +2 °C. Возврат начинается с обычного максимума.

## Как регулируется ядро

Каждая карта имеет своё состояние и таймеры по UUID. Верхний предел — её текущая фиксация в HiveOS; отдельного максимума в TOML нет. Рабочая частота может отличаться от заданной, поэтому подтверждение фиксации читается через `nvtool`, а рабочая частота показывается отдельно. Поддержка и округление фиксации зависят от GPU/драйвера: [NVIDIA SMI](https://docs.nvidia.com/deploy/nvidia-smi/index.html).

Исходные правила:

| Условие для карты | Действие |
| --- | --- |
| ≥68 °C непрерывно 180 с и обе системы вентиляторов достигли своих настроенных максимумов (допуск 2 пункта) | −50 МГц, повторение каждые 180 с до минимума |
| ≤65 °C непрерывно 180 с | +50 МГц, повторение до частоты HiveOS |
| Между порогами либо есть запас обдува | Сохранение частоты |
| ≥75 °C | Немедленный минимум независимо от вентиляторов и таймеров |

При аварии восстановление тоже требует непрерывного охлаждения. Ошибки измерения запрещают повышение; сохранённое ограничение не снимается при остановке или перезапуске. Изменение HiveOS/порогов сбрасывает таймеры. Если фиксация HiveOS выключена или ниже минимума, управление картой приостанавливается. Память, смещение ядра, power limit и GPU-вентиляторы регулятор не меняет. Остановка майнера при критической температуре остаётся функцией HiveOS.

```toml
[defaults]
min_core_mhz = 2400
step_mhz = 50
hot_c = 68
cool_c = 65
hot_hold_seconds = 180
cool_hold_seconds = 180
emergency_c = 75

# Пример индивидуального переопределения: подставьте UUID из своего файла.
[gpu."GPU-00000000-0000-0000-0000-000000000001"]
min_core_mhz = 2300
```

Файл: `/etc/cryptone-core-control.toml`. Корректные параметры подхватываются за 5 с, ошибочная версия отклоняется целиком. При ошибке частотный регулятор сохраняет предыдущие настройки и запрещает повышение. При цели GPU AutoFan 66 °C восстановление всё равно требует фактических ≤65 °C.

## Изменение оборудования, обновление и диагностика

При добавлении/удалении карты или смене PWM нужно остановить обе службы и заново проверить состав и разъём. Это намеренная защита: исчезнувшая карта не должна незаметно исключаться из контроля. Пошаговая процедура, обновление с частной версии и удаление описаны в [MAINTENANCE.md](MAINTENANCE.md).

```bash
systemctl status cryptone-fan-control cryptone-core-control
journalctl -u cryptone-fan-control -u cryptone-core-control -n 60 --no-pager
fancheck --json
```

Перед публикацией логов удалите UUID, названия воркеров, адреса и токены доступа. Файлы конфигурации в корне репозитория содержат **вымышленные UUID и пример PWM**; устанавливать их напрямую нельзя. Для установки используйте `configure.py`.

## Разработка

Зависимости Python не требуются. Тесты моделируют оборудование и не запускают майнер, `nvidia-smi` или службы:

```bash
python3 -m unittest discover -q
python3 -m compileall -q .
python3 -m py_compile fancheck fanset
```

Проверяются наборы из 1, 2, 3, 4, 8, 12, 16 и 64 карт, независимость таймеров, аварии, ограничения, атомарная запись, применение настроек, повреждённые статусы, выбор PWM и транзакция установки. Моделирование не заменяет испытания конкретного оборудования. CI запускает эти проверки на Python 3.11–3.13.

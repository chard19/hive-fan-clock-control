# Обслуживание

## Добавление/удаление GPU или смена PWM

Горячая замена карт не поддерживается. Выключите риг перед физическими работами. Пока вы проверяете программные настройки, остановите регулятор частот первым, затем корпусный. Остановка корпуса запрашивает 100%; остановка ядра сохраняет последнее ограничение частоты.

```bash
sudo systemctl stop cryptone-core-control.service
sudo systemctl stop cryptone-fan-control.service
```

Сохраните копию обоих файлов `/etc/cryptone-*.json`/`*.toml`, unit-файлов и `/var/lib/cryptone-core-control/state.json` вне репозитория. Не публикуйте полученные UUID и статусы вместе с кодом.

После изменения оборудования снова выполните `python3 configure.py --list`. Выберите корпусный канал, создайте **новую** папку конфигурации, например `--output build-new`. Перед заменой файлов перенесите желаемые пороги и настройки `fanset`, а также индивидуальные переопределения из старого TOML. Удалённые UUID нужно убрать из обоих списков и из разделов `[gpu]`. Новый список включает все физические NVIDIA, видимые `nvidia-smi`.

После проверки установите оба файла и проверьте их до запуска:

```bash
sudo install -m 0644 build-new/cryptone-fan-control.json /etc/cryptone-fan-control.json
sudo install -m 0644 build-new/cryptone-core-control.toml /etc/cryptone-core-control.toml
sudo /usr/bin/python3 /usr/local/sbin/cryptone-fan-control.py --check
sudo /usr/bin/python3 /usr/local/sbin/cryptone-core-control.py --check
sudo systemctl start cryptone-fan-control.service
sudo systemctl start cryptone-core-control.service
fancheck
```

Повреждённую или неоднозначную привязку PWM программа отклоняет. При повторном появлении того же `hwmonN` с другим устройством она не переключается на него. Если драйвер исчез, запись аварийных 100% также невозможна: проверьте охлаждение физически.

## Обновление и переход с частной версии

`install.py` намеренно отказывается обновлять установленную систему. Старая частная версия имеет другой формат аппаратной привязки; запускать поверх неё новую службу со старым JSON нельзя.

1. Получите новую версию в отдельную папку и запустите все тесты.
2. Сделайте резервную копию установленных скриптов, двух конфигураций, двух unit-файлов и состояния частот. Запишите, какие службы были включены.
3. Остановите сначала ядро, затем корпус. Проверьте полное охлаждение. При необходимости остановите майнинг штатными средствами на время обслуживания.
4. Создайте конфигурацию через `configure.py`; сверяйте канал по проверенному подключению, а не только по номеру `hwmonN`. Сохраните нужные настройки и индивидуальные переопределения. В TOML не должно быть `max_core_mhz`: максимум берётся из HiveOS.
5. Замените скрипты в `/usr/local/sbin/` и команды в `/usr/local/bin/` согласно таблице ниже. Установите новые конфигурации и unit-файлы с правами 0644, исполняемые файлы — 0755. Не удаляйте сохранённое состояние частот.
6. Выполните `--check` обеих служб, `systemd-analyze verify` unit-файлов и `systemctl daemon-reload`. Запустите корпус, затем ядро. Проверьте `fancheck`, журналы, фиксации и физическое вращение вентиляторов. Это обновление требует перезапуска служб.
7. Если проверка не прошла, остановите обе службы, восстановите **согласованный комплект** старых скриптов/конфигураций/unit-файлов из резервной копии, выполните `daemon-reload` и запустите прежнюю версию. Не подменяйте сохранённое состояние более высокой частотой ради устранения ошибки.

| Файл репозитория | Место установки |
| --- | --- |
| `cryptone-fan-control.py` | `/usr/local/sbin/cryptone-fan-control.py` |
| `core_control.py` | `/usr/local/sbin/cryptone-core-control.py` |
| `fancheck`, `fanset` | `/usr/local/bin/` |
| Сгенерированные JSON и TOML | `/etc/` |
| Два файла `*.service` | `/etc/systemd/system/` |

Не копируйте шаблоны с вымышленными UUID в `/etc/`. Модуль датчиков устанавливается отдельно подходящим способом для вашей платы; служба больше не загружает `it87` автоматически. Обновление и удаление не должны убирать нужный драйвер датчиков из системы.

## Остановка и удаление

```bash
sudo systemctl disable --now cryptone-core-control.service
sudo systemctl disable --now cryptone-fan-control.service
```

Корпус остаётся на 100%, а применённые фиксации ядра сохраняются. Для возврата частот примените свой штатный профиль HiveOS из панели. Для возврата аппаратного управления вентиляторами используйте проверенные настройки BIOS или документированный автоматический режим своего hwmon-драйвера. Не возвращайте неизвестный режим либо старый низкий PWM во время нагрузки.

После проверки охлаждения и резервной копии можно удалить установленные файлы из таблицы и выполнить `sudo systemctl daemon-reload`. Файлы конфигурации и `/var/lib/cryptone-core-control/state.json` лучше сохранить до завершения обслуживания. Удаление этих файлов само по себе не возвращает аппаратные настройки.

## Что означает предупреждение

| Сообщение | Проверка |
| --- | --- |
| Максимум PWM достигнут | Цель не удерживается при выбранном максимуме; проверьте обдув и ограничения |
| Аварийное охлаждение 100% | Температуры, состав GPU, корректность JSON и журнал корпусной службы |
| Применение `fanset` не подтверждено | Статус службы, время показаний и `fanset --show` |
| Фактический PWM вне границ | Конкурирующее ПО, BIOS и правильность выбранного канала |
| Состав GPU различается | Пропавшая/добавленная карта или несогласованные списки UUID |
| Пауза управления | Выключенная фиксация HiveOS или частота ниже выбранного минимума |
| Ошибка датчиков/применения | `nvidia-smi`, `nvtool`, драйвер и журнал; автоматическое повышение блокируется |

При ошибке одного источника `fancheck` сохраняет остальные доступные разделы. Подробности доступны в `fancheck --json`; код завершения 1 означает наличие предупреждений, включая температурную аварию или недостижение цели.
